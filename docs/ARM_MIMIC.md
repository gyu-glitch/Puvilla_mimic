# 서 있는 모델 팔 미믹 — 레퍼런스 반영 검토본

2026-10-20. 사용자가 제공한 `7629.png`의 두툼한 팔, 얼굴 옆 손 위치, 안쪽 엄지와 정면 손바닥을 기준으로 수정했다. 이전 `wave-front.png` / `wave-angle.png`는 반려된 결과다. 현재 결과는 `codex-arm-connected-wave-0.png`, `codex-wave.mp4`, `codex-wave.gif`다. 사용자 합격 판정을 받았다는 뜻은 아니다.

## 현재 구현

- 원본 `pu_stand.obj`의 연결된 쿼드 메쉬를 그대로 쓴다. 팔을 자르거나 다른 모델로 대체하지 않는다. 원본 OBJ와 목도리 바이너리 해시는 기준본과 같다.
- `build-standing-rig.mjs`는 원본 연결 관계로 팔 영역을 찾는다. 어깨 회전 중심은 경계 고리보다 3cm 아래에 둔다. 팔꿈치 가중치는 중심축에 수직인 단면을 기준으로 12cm 구간에서 보간한다.
- `standingArmSurface.ts`는 팔 영역만 dual quaternion 스키닝으로 변형해 큰 회전에서 부피가 줄어드는 문제를 줄인다. 몸 중앙과 얼굴은 기존 변형을 유지한다.
- 아래팔 단면을 연속적으로 회전시켜 손의 넓은 면과 안쪽 엄지가 보이게 한다. 손 끝은 들었을 때 반경을 최대 20% 확장하며, 내린 상태에는 적용하지 않는다. 손가락 개별 리깅은 아니다.
- 카메라 입력에서는 Pose의 검지·새끼손가락 사이 방향을 신뢰도와 길이 검사 후 반영한다. 검출 불량이면 기본 방향으로 부드럽게 돌아간다. 손 관절 전용 모델을 추가한 것은 아니다.
- 아래로 내린 입력은 몸통 간섭을 줄이는 0.43rad의 여유각에 대응한다. 수평 위에서는 실제 팔 각도를 따라간다.
- `standingWave.ts`는 레퍼런스 검토용 입력이다. 위팔 2.4rad, 아래팔 2.86rad, 작은 ±0.08rad 흔들기를 같은 실시간 리타기팅 경로에 넣는다. 고정 모양을 사진에 합성한 것이 아니다.
- 얼굴, 목도리, 배경, vendor 유화 필터는 수정하지 않았다.

Pose 인덱스 근거: https://github.com/google-ai-edge/mediapipe/blob/master/mediapipe/tasks/python/vision/pose_landmarker.py

## 실행

- 실제 미믹: http://localhost:4175/
- 손인사 데모: http://localhost:4175/?sim=1&armdemo=wave
- 여러 방향 입력: http://localhost:4175/?sim=1&armdemo=1
- 자세·시점 검증: http://localhost:5175/dev/arm-lab.html?pose=wave&look=final&crop=portrait&hold=1&bg=winter

데모는 카메라를 사용하지 않으며, 팔이 잘 보이도록 화면 구도만 별도로 맞춘다. 일반 미믹도 팔이 보이도록 Codex 전용 구도를 넓혔다. 세로 화면은 폭에 맞추고 추가 높이를 캐릭터 중심에 나눠 손이 잘리지 않게 한다. 외부 주소는 https://nau-gyuchan.tailc22fe0.ts.net:10000/ 이며 연결 및 렌더를 확인했다. 기존 공개 443과 클로드 8443 연결은 유지한다.

## 검증 범위

- 타입 검사, Vite 배포 빌드, 원본 해시·964개 중앙/머리 정점 보호·좌우 관절 대칭 검사 통과.
- 미러링, 팔 가림 유지/해제, NaN 회복, 얼굴과 몸 연결 검사 통과.
- 손 방향 미러링, 검출 불량/퇴화한 손 방향 폐기, 작은 흔들기와 고정된 어깨 입력 검사 통과.
- 브라우저에서 정면, 45도, 90도, 반대손, 12초 들고 내리는 한 주기, 실제 배포본을 확인했다. 최종 프레임과 6초 실제 캔버스 녹화를 보관했다. 검토 PC에서는 녹화하지 않을 때 약 54~57fps를 관찰했다.
- 외부 HTTPS 주소에서 최신 빌드를 열고, 390×844 세로 뷰포트에서도 손이 잘리지 않는 것을 확인했다. 실제 휴대폰 하드웨어의 성능 검사는 아니다.
- 실제 사람이 카메라 앞에서 수행하는 움직임, 다양한 가림·교차 자세와 모바일 성능은 아직 대조하지 못했다. 시뮬레이션 결과만으로 실사용 추적까지 검증됐다고 주장하지 않는다.

`npm run rig:build` → `npm run rig:check` → `npm run deploy`. 모두 Codex 전용 폴더에서 실행한다.

검증 페이지의 저장은 개발 서버 전용 `/__mimic/capture`를 사용한다. 로컬 동일 출처, 이름·형식·크기를 제한하며 `docs/arm-review`에 생성 렌더만 기록한다. `scripts/export-wave-review.py`는 실제 녹화를 MP4/GIF로 변환한다.
